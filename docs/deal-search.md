# Поиск и связанные сделки компании

Авторизованный `GET /deals` принимает дополнительные параметры:

- `search`: до 200 символов, поиск без учёта регистра по названию/сокращению/ИНН заказчика и исполнителя, названию материала или полному ID сделки. Специальные символы трактуются буквально.
- `companyId`: ID компании в роли заказчика **или** исполнителя.
- Существующие `customerId`, `providerId`, `materialId`, `userId`, этап и остальные фильтры продолжают работать и объединяются с новыми условиями.
- `page`: от 1; `page_size`: от 1 до 200. Ответ сохраняет `items`, `total`, `page`, `pageSize`, `totalPages`, `hasNext`, `hasPrev`.

Пример: `GET /deals?companyId=COMPANY_ID&search=Песок&page=1&page_size=20&includeRelations=true&includeDeleted=false`.

Права применяются до поиска и пагинации: обычный сотрудник видит только свои сделки независимо от переданного `userId`, руководитель/администратор может выбирать сотрудника. По умолчанию удалённые сделки исключены. Поиск не меняет эти правила.

При текстовом поиске строки и общий счётчик возвращаются одной агрегацией `$facet`. Сортировка дополнена `_id` для устойчивой пагинации. Ошибка MongoDB возвращает 500, а не успешный пустой список.

Миграция данных и новый индекс не требуются. Поиск подстроки через связи не является полнотекстовым индексом; при большом объёме данных стоит отдельно оценить explain и индексированный поисковый документ.
