# Лиды и задачи до сделки

Все запросы требуют `Authorization: Bearer <token>`. Обычный пользователь
работает со своими лидами и задачами. Пользователи с `admin=true` или
`manager=true` видят все записи и могут назначать другого ответственного.
Это соответствует действующим правам на сделки. В текущей модели
`manager=true` означает повышенные права руководителя.

Компания хранит реквизиты и контакты. Лид хранит конкретную потенциальную
потребность, поэтому у одной компании может быть несколько лидов.
Материал, цена, компания и объём необязательны на этапе создания лида.

## Этапы воронки

`GET /lead-stages` возвращает отдельный справочник этапов лидов. При запуске
API миграция создаёт начальные этапы:

| kind | Название | Правило |
| --- | --- | --- |
| new | Новый | По умолчанию при создании |
| in_progress | В работе | Установление контакта и выяснение потребности |
| qualified | Квалифицирован | Из этого этапа можно создать сделку |
| deferred | Отложен | При переходе требуется nextContactAt |
| unqualified | Нецелевой | Требуется lossReason |
| converted | Переведён в сделку | Устанавливается через convert |

Клиент использует `_id` этапа как `stageId`. `kind` определяет поведение,
`name` является редактируемым названием, `order` задаёт порядок колонок.

Руководитель и администратор могут управлять справочником:

```http
POST   /lead-stages
PATCH  /lead-stages/{id}
DELETE /lead-stages/{id}
```

Создание этапа:

```json
{"name": "Выясняем потребность", "kind": "in_progress", "order": 1}
```

Нельзя удалить используемый этап или последний этап типа `new`/`converted`.
Нельзя менять тип системного или используемого этапа. Существующий `/stages`
продолжает обозначать только этапы сделок.

## Создание и обработка лида

```http
POST /leads
```

Минимальный запрос:

```json
{"title": "Первичный контакт с потенциальным заказчиком"}
```

Расширенный запрос:

```json
{
  "title": "Закупка песка для нового объекта",
  "companyId": "COMPANY_OBJECT_ID",
  "contactPerson": {
    "name": "Иван Петров",
    "position": "Начальник снабжения",
    "phones": ["+7 999 123-45-67"],
    "emails": ["ivan@example.com"]
  },
  "source": "Входящий звонок",
  "priority": "urgent",
  "materialIds": ["MATERIAL_OBJECT_ID"],
  "quantity": 100,
  "unitMeasurement": "т",
  "objectAddressId": "ADDRESS_OBJECT_ID",
  "budget": 150000,
  "expectedPurchaseAt": "2027-03-20T09:00:00+03:00",
  "notes": "Нужна доставка на объект"
}
```

`contactPerson` хранит снимок выбранного контактного лица. Поле компании
`contacts` с данными ФНС этим процессом не изменяется.

Приоритеты: `low`, `normal`, `high`, `urgent`. Ответственный `ownerId`
по умолчанию равен текущему пользователю. `objectAddress` позволяет указать
объект текстом; `objectAddressId` ссылается на существующий адрес компании.

```http
GET    /leads?page=1&pageSize=100
GET    /leads?status=new
GET    /leads?stageId={stageId}&priority=urgent
GET    /leads?companyId={companyId}
GET    /leads?ownerId={userId}&search=песок
GET    /leads/{id}
PATCH  /leads/{id}
DELETE /leads/{id}
```

Список возвращает пагинацию `items`, `total`, `page`, `pageSize`,
`totalPages`, `hasNext`, `hasPrev`. В элементах списка и карточке приходят
`company`, `stage`, `materials`, если связанные записи найдены.

PATCH изменяет только переданные поля. Для очистки необязательных полей
можно передать `null`, для очистки материалов — `materialIds: []`.
`title`, `ownerId`, `stageId`, `priority`, `materialIds` нельзя обнулить.

Отложить до сезона:

```http
PATCH /leads/{id}
```

```json
{
  "stageId": "DEFERRED_LEAD_STAGE_ID",
  "nextContactAt": "2027-03-15T10:00:00+03:00",
  "notes": "Вернуться перед строительным сезоном"
}
```

Дата `nextContactAt` автоматически создаёт задачу типа `call`. В ответе
приходит её `followUpTaskId`. Изменение даты переносит существующую открытую
задачу. Завершение, отмена или удаление этой задачи очищает следующий контакт.
Чтобы отменить звонок PATCH-запросом к лиду, передайте `nextContactAt: null`;
если лид отложен, одновременно переведите его в другой этап.

Пометить нецелевым:

```json
{
  "stageId": "UNQUALIFIED_LEAD_STAGE_ID",
  "lossReason": "Не закупает нерудные материалы"
}
```

Запланированный автоматический звонок отменяется. Лид можно вернуть в работу.
Удаление лида мягкое; сначала необходимо закрыть его остальные открытые задачи.
Удалять или редактировать переведённый в сделку лид нельзя.

## История контактов

```http
GET  /leads/{id}/activities?page=1&pageSize=100
POST /leads/{id}/activities
```

```json
{
  "type": "call",
  "comment": "Поговорили со снабжением. Закупка ожидается в марте."
}
```

Ручные типы: `note`, `call`, `meeting`, `email`. API также записывает
создание лида, изменения, смену этапа, действия с задачами и перевод в сделку.
Каждое событие содержит `userId`, `createdAt`, `type`, `comment`, `details`.

## Задачи менеджера

```http
POST /tasks
```

```json
{
  "title": "Уточнить объём и дату поставки",
  "type": "call",
  "dueAt": "2027-03-15T10:00:00+03:00",
  "companyId": "COMPANY_OBJECT_ID",
  "leadId": "LEAD_OBJECT_ID",
  "comment": "Позвонить Ивану"
}
```

Обязательны `title` и `dueAt`. Типы: `call`, `meeting`, `email`, `other`.
Состояния: `open`, `completed`, `cancelled`. Можно создать самостоятельную
задачу или связать её с компанией, лидом, сделкой. Связанные записи проверяются
на существование, соответствие компании и права ответственного.

Все даты-время в запросах должны содержать часовой пояс. Для календарных
фильтров используется `timezone=Europe/Moscow`, его можно изменить.
В ответах даты новых лидов, задач и событий возвращаются в UTC с часовым поясом.

```http
GET   /tasks?bucket=today
GET   /tasks?bucket=overdue
GET   /tasks?bucket=upcoming
GET   /tasks?leadId={leadId}&status=open
GET   /tasks?companyId={companyId}
GET   /tasks?dealId={dealId}
GET   /tasks?ownerId={userId}&type=call
GET   /tasks?dateFrom=2027-03-01&dateTo=2027-03-31
GET   /tasks/{id}
PATCH /tasks/{id}
DELETE /tasks/{id}
```

Списки задач пагинируются. `bucket` выбирает только открытые задачи:
`today` — на сегодняшний день, `overdue` — со сроком раньше текущего времени,
`upcoming` — с завтрашнего дня. Сроки календарного дня считаются в указанном
часовом поясе. Просроченная задача сегодня может попасть в оба первых списка.

Перенести задачу:

```json
{"dueAt": "2027-03-17T14:00:00+03:00"}
```

Завершить с результатом:

```json
{"status": "completed", "result": "Клиент подтвердил закупку 100 тонн"}
```

Отменить:

```json
{"status": "cancelled", "comment": "Клиент отказался"}
```

## Перевод в сделку

Переведите лид в этап типа `qualified`, затем:

```http
POST /leads/{id}/convert
```

```json
{
  "serviceId": "SERVICE_OBJECT_ID",
  "stageId": "DEAL_STAGE_OBJECT_ID",
  "materialId": "MATERIAL_OBJECT_ID",
  "quantity": 100,
  "amountSalesUnit": 1500
}
```

Тело использует поля существующего `POST /deals`. `stageId` здесь обозначает
этап сделки. Компания подставляется в `customerId`. Если компания пока
не указана у лида, передайте `customerId`. Если выбран один материал,
он подставляется автоматически. Объём, единица измерения, объект и комментарий
также подставляются, если их не передали в запросе.

Ответ содержит `{ "lead": {...}, "deal": {...} }`. У лида заполняются
`dealId`, `convertedAt`, этап `converted`; у сделки — `_id`, `sourceLeadId`.
Ответственным сделки остаётся владелец лида. Автоматический следующий звонок
отменяется, прочие задачи и история сохраняются.
Компания получает роль `customer`; её прежние роли сохраняются.

Повторный вызов возвращает уже созданную сделку. Одновременные запросы
используют один зарезервированный ID. Если перевод прервался, у лида
`conversionPending=true`: повторите convert для завершения с первоначальными
данными. Редактирование лида на время перевода заблокировано.

## Excel

```http
POST /companies/import?createLeads=true
POST /companies/import?role=customer&createLeads=true
```

Файл передаётся в multipart-поле `file`, как и раньше. Опция `createLeads`
по умолчанию выключена. Для каждой успешно обработанной компании создаётся
первичный лид текущего менеджера. При повторном импорте первичный лид для
той же компании и менеджера повторно не создаётся, даже если ранее закрыт.
Дополнительную потребность можно завести вручную через `POST /leads`.

К прежнему отчёту импорта добавлены `leadsCreated` и `leadsSkipped`.
Компании из архива пропускаются с ошибкой строки; остальные строки обрабатываются.
Миграция `leads_tasks_v1` создаёт справочник и индексы при запуске API;
существующие компании и сделки автоматически в лиды не преобразуются.
